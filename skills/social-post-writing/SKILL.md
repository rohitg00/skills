# Social Post Writing

Use this skill as a conversational writing partner for social posts. Do not assume the user is writing about tech, startups, AI, career, business, personal branding, or any other fixed domain. First understand what they want to say, why they want to say it, who should read it, and how it should sound.

The job is not to force a template. The job is to help the user find the clearest version of their idea, then adapt it to the platform.

## Conversation First

Start with a short brief. If the user already gave enough context, draft immediately and state any assumptions. If the request is thin, ask only the most useful 3-6 questions instead of sending a long intake form.

Ask about:

- Topic: what do you want to write about?
- Platform: LinkedIn, X/Twitter, Threads, Bluesky, Instagram, Reddit, HN, newsletter snippet, or multi-platform?
- Audience: who should read it?
- Goal: inform, announce, reflect, persuade, invite, sell, recruit, teach, entertain, ask for feedback, or start a discussion?
- Core point: what is the one thing readers should take away?
- Material: story, example, photo, link, data, quote, source, product, event, lesson, or draft.
- Tone: casual, warm, sharp, expert, funny, reflective, polished, direct, skeptical, celebratory, vulnerable, or restrained.
- CTA: none, comment, click, sign up, buy, attend, reply, share, give feedback, or DM.
- Boundaries: claims to avoid, words to avoid, topics to avoid, emoji preference, hashtag preference, length, and formality.

Good first response when context is missing:

```text
I can write it. Quick brief first:

1. What do you want the post to be about?
2. Which platform is it for?
3. Who should it speak to?
4. What should readers do or feel after reading?
5. Any tone you want: casual, polished, sharp, warm, funny, or something else?
```

Good response when context is enough:

```text
I will draft this for LinkedIn with a warm, concise tone. I am assuming the goal is to share the lesson and invite discussion, not sell anything.
```

## Default Posture

- Preserve the user's point of view.
- Make the post sound like a person, not a content calendar.
- Match the user's domain instead of importing one.
- Ask before inventing stories, results, metrics, credentials, quotes, or lived experience.
- Keep one central idea per post unless the user asks for a thread or carousel.
- Make claims concrete: examples, context, source, scene, before/after, or clear caveat.
- Use platform conventions without copying influencer formulas.
- Offer 2-3 options when the best angle is ambiguous.

## Universal Workflow

1. Clarify the brief.
2. Extract the core idea in one sentence.
3. Choose the best angle: story, lesson, announcement, opinion, question, proof, transformation, list, or resource.
4. Pick the platform shape.
5. Draft in the requested tone.
6. Run the anti-slop pass.
7. Check claims, names, links, dates, numbers, and platform limits.
8. Return ready-to-post copy plus concise notes only when useful.

## Platform Routing

| Platform | Best For | Shape |
|---|---|---|
| LinkedIn | context, credibility, lessons, career, business, community, launches | hook, short paragraphs, optional bullets, soft CTA |
| X/Twitter | one sharp idea, timely thought, short update, thread, quote, link | compressed, one idea, no hashtags by default |
| Threads / Bluesky | conversational notes, community discussion, lightly polished takes | natural tone, short paragraphs, gentle replies |
| Instagram | caption tied to an image, personal story, creator update, brand moment | visual-first caption, line breaks, optional hashtags |
| Reddit | community-specific question, transparent launch, discussion, request for advice | plain title, context, details, no hype |
| Hacker News | Show HN, technical project, clear link, substantial discussion | factual title, concise body, implementation detail |
| Multi-platform | campaign, launch, event, article, product, announcement | one source idea adapted per channel |

## LinkedIn Rules

Use LinkedIn when the post needs context, story, reflection, credibility, or room for examples.

Format:

- First line should make the reader want line two.
- Prefer 800-1,600 characters unless the user asks for short or long.
- Use short paragraphs.
- Use bullets only when they improve scanning.
- Use emojis only if they match the user's style.
- Use 0-5 hashtags only when requested or useful.
- Use one CTA max.

Good LinkedIn structures:

### Story To Lesson

```text
<Specific moment or realization>.

I noticed it while <real context>.

What happened:
- <detail>
- <detail>
- <detail>

The lesson:
<clear takeaway>

<soft CTA or closing thought>
```

### Announcement

```text
<Clear announcement>.

Why it matters:
<context for the audience>

What is included:
- <specific detail>
- <specific detail>
- <specific detail>

<link or next step>

<soft CTA>
```

### Opinion

```text
<Direct opinion>.

The reason:
<specific explanation>

Where this shows up:
- <example>
- <example>
- <example>

The caveat:
<honest limitation>

<question or closing line>
```

LinkedIn hooks that work:

- A specific result: "I changed one part of the process and the whole meeting got shorter."
- A grounded surprise: "The hard part was not the launch. It was explaining it simply."
- A useful mistake: "I almost posted the wrong lesson from this."
- A clear tension: "People wanted the outcome, but not the workflow that created it."
- A concrete moment: "The best feedback came from the person who nearly skipped the call."

LinkedIn hooks to avoid:

- "I'm excited to share..."
- "Here's the thing..."
- "In today's fast-paced world..."
- "Nobody is talking about..."
- "Agree?"
- "Thoughts?"
- "Drop a comment..."

## X/Twitter Rules

Use X/Twitter when the idea is sharp, timely, compact, quotable, or works as a short sequence.

Single posts:

- Stay under 280 characters.
- Aim for one idea.
- Cut setup aggressively.
- No hashtags unless requested or event-specific.
- Use line breaks sparingly.
- Make links fit naturally.

Good single-post structures:

```text
<Observation>.

<Specific reason, example, or implication>.
```

```text
<Thing that happened>.

The useful part: <lesson>.
```

```text
<Opinion>.

<Caveat or proof>.
```

Threads:

- First post must stand alone.
- Each reply should add one new point.
- Number only when sequence matters.
- End with synthesis, not engagement bait.
- Keep each post scannable without padding.

Thread shape:

```text
1/ <Standalone hook with the whole idea>

2/ <Context or scene>

3/ <Evidence, example, or story>

4/ <Tradeoff, caveat, or mistake>

5/ <Takeaway or next step>
```

X/Twitter patterns to avoid:

- "Unpopular opinion:"
- "The uncomfortable truth:"
- "Let that sink in."
- all-caps emphasis.
- dramatic ellipses.
- forced one-line fragments.
- generic engagement prompts.

## Threads / Bluesky Rules

Use these when the user wants a conversational post with less polish and more immediacy.

- Keep the idea compact.
- Let the voice feel like a real note to peers.
- Ask a genuine question if the user wants discussion.
- Avoid hashtags by default.
- Avoid over-structured list posts unless requested.

Good shape:

```text
Small thing I keep noticing:

<observation>

I think it matters because <reason>.
```

## Instagram Caption Rules

Use Instagram when the text supports an image, carousel, reel, event, personal update, product visual, artwork, place, food, fitness, fashion, creator work, or brand moment.

Before writing, ask what the image/video shows if it was not provided.

Format:

- First line should connect to the visual.
- Caption can be short, story-led, poetic, practical, or promotional depending on the user.
- Emojis and hashtags are optional, not automatic.
- If selling or promoting, make the next step clear.
- If the post is personal, preserve the user's natural language.

Caption shapes:

```text
<Line that names the moment or feeling>.

<Short context or story>.

<CTA or closing line>
```

```text
<What people are seeing>.

<Why it matters or what changed>.

<Optional hashtags>
```

## Reddit Rules

Use Reddit when the post belongs to a specific community and should invite real discussion.

- Match the subreddit norms if known.
- Be transparent about affiliation.
- Lead with the community's problem, not self-promotion.
- Include enough context for strangers.
- Ask for specific feedback.
- Avoid hype, sales language, and broad claims.

Good shape:

```text
Title: <Plain, specific title>

Body:
<Context>

What I have tried / built / noticed:
- <detail>
- <detail>
- <detail>

Question:
<specific ask>
```

## Hacker News Rules

Use HN only when the post has enough substance for a technical, skeptical, or maker audience.

- Title should be factual.
- Explain what it is in one sentence.
- Include technical or implementation detail when relevant.
- Avoid marketing copy.
- If it is a Show HN post, make the link and purpose clear.

Good shape:

```text
Title: Show HN: <Name> - <specific capability>

Body:
<One sentence purpose.>

Details:
- <implementation detail>
- <tradeoff>
- <who it is for>

Link: <URL>
```

## Multi-Platform Repurposing

When adapting one idea for multiple platforms, create a source idea first.

```text
Core idea:
<one sentence>

LinkedIn:
<context-rich version>

X/Twitter:
<compressed version>

Threads / Bluesky:
<conversational version>

Instagram:
<visual-first caption>

Reddit/HN:
<community-first version>
```

Do not cross-post identical text everywhere. Preserve the same idea, but change the shape, length, proof, and CTA for each platform.

## Tone Menu

If the user does not know what tone they want, offer a small menu:

- Casual: sounds like a clear note to peers.
- Warm: generous, personal, and human.
- Sharp: direct, opinionated, and compressed.
- Expert: precise, credible, and measured.
- Playful: lighter rhythm without becoming gimmicky.
- Reflective: slower, story-led, and honest.
- Celebratory: positive without becoming inflated.
- Skeptical: careful, caveated, and evidence-led.
- Educational: practical, structured, and useful.
- Community-first: humble, transparent, and discussion-oriented.

## Anti-Slop Pass

For a stricter cleanup pass, load the anti-slop reference files if they are available in this skills collection:

- `../anti-slop-writing/references/phrases.md`
- `../anti-slop-writing/references/structures.md`
- `../anti-slop-writing/references/examples.md`

Before finalizing every post:

- Cut throat-clearing.
- Remove formulaic contrast unless the contrast is genuinely useful.
- Replace vague claims with specific examples.
- Remove fake urgency.
- Remove fake profundity.
- Remove repeated three-item rhythms.
- Remove business jargon unless the user's audience uses it naturally.
- Remove engagement bait.
- Avoid generic "journey", "game-changer", "unlock", "delve", "leverage", and "transform" language.
- Check whether the post sounds like the requested person or brand.
- Keep useful texture: context, tradeoffs, limitations, and real details.

## Hashtag Rules

- LinkedIn: 0-5 relevant hashtags when requested or useful.
- Instagram: 0-12 hashtags depending on the user's style and audience.
- X/Twitter, Threads, Bluesky: no hashtags unless requested or tied to an event.
- Reddit/HN: no hashtags.

Never add hashtags just to make the post look "social".

## Character Discipline

If a post is too long:

1. Remove setup.
2. Remove adjectives.
3. Replace abstract nouns with concrete words.
4. Cut the second idea.
5. Move context into a reply or comment.
6. Ask whether the user wants a shorter version if the tone would suffer.

## Output Format

When more context is needed:

```text
Questions:
1. <question>
2. <question>
3. <question>
```

Single platform:

```text
Draft:
<final post>
```

Multiple options:

```text
Option 1 - <angle>:
<post>

Option 2 - <angle>:
<post>
```

Multi-platform:

```text
Core idea:
<one sentence>

LinkedIn:
<post>

X/Twitter:
<post>

Threads / Bluesky:
<post>

Instagram:
<caption>

Reddit/HN:
<post>
```

For X/Twitter, include a character count when useful.

## Final Checklist

- [ ] Topic and platform are clear.
- [ ] Audience and goal are clear.
- [ ] Tone matches the user's request.
- [ ] The post has one central idea.
- [ ] Claims, numbers, names, dates, and links are verified or caveated.
- [ ] No invented metrics, stories, quotes, or lived experience.
- [ ] CTA fits the user's goal.
- [ ] Platform length and format fit.
- [ ] No engagement bait.
- [ ] Anti-slop pass completed.
- [ ] Final copy is ready to post.
